## 一、我们在做什么（不可动摇的几条）

1. **一处所一条目**。内容库里每个主体只存在一条条目，该条可以很长；各分站按自身主题**抽取其中不同部分**，不复制内容。唯一性检查已内置到校验器，且**是跨站的**。
2. **一站一视图**。分站是从库按主题投影出来的视图，不拥有内容。不得为凑网页而写条目。
3. **三条质量底线**：内容极其丰富（七维：身份、来历、形制、制度、人物、生活、限度）；内容极其专业（专业＝可核查，靠 `locator` 而不是靠权威口吻）；来源覆盖一切与溧水相关的事物。
4. **库优先、网站派生**。库建完美后从库派生多个网站。当前一切工作都在库这一层。
5. **范围收窄（2026-09-30 用户定夺，优先遵循）**：产业定位、经济、农业园区、影视基地、研学线路、高校、交通设施**暂缓**，来源卡保留但不建条目；**以历史、人文为主轴**，作为参考之用。
6. **六步流程**：尽可能搜集 → 分辨是否确实可信 → 重新整理 → 生成 Markdown 基础数据 → 在基础数据上建各分站 → 所有搜集内容留痕、注明来源。

## 八、工作方法（照做即可，不要重新发明）

1. **先记来源卡，再改条目**。任何新读到的志文材料，先追加进来源卡（含逐字原文与使用注意），再动条目。本轮三次都是这个顺序。
2. **要派 agent 建条，先把志文原文逐字存进来源卡**，让 agent 读原文而不是读我的转述。任务书必须写死：禁止联网、禁止使用对历史人物的既有知识、引文逐字照来源卡、年号与干支不换算公元、枚举字段两语稿一律写中文、必须有「存疑之处」一节、指定哪几条由我本人写不许 agent 动。
3. **agent 自报的完成度必须用机器对账**，不接受自报。做法：把来源卡的名录名单与条目标题逐一比对。本轮就是靠这个抓出 agent 漏写的周邠（领 13 人交回 12 对）。
4. **同名陷阱一律「本库无材料判定，不作认定」，且不用 `distinct_from`**——单方声明 `distinct_from` 等于断为两人。已遇到的同名对：李衡（宋／元）、杨白海／杨木海、张璲族子张锡／张锡、张问道／张问行、严恪／严晃、黄恒／黄养性／黄明诏、陈福／陈某／陈永、傅应祯／傅御史、两处「表孝」「昭孝」里名。
5. **年号与干支不换算公元；繁体照录；转录本校勘括号「（误字）［正字］」与缺字「□」照原样**。标题用简体、引文用繁体。
6. **多处并存就并列，不取舍、不平均、不推定先后**。例：天启元年三十八户／天启二年改折／忠节传四十五家三处并存；封与赠两式；之驊与之骊两式；名宦传「历兴化太守」与孝子传「時在比部」。
7. **志文所载之说必须标明**：感应、梦兆、异说、远祖、评语，一律照录并标为志文之说，不作事实记述。
8. **卷次次序不可用作任职先后之据**。康熙志卷六把周邠（元丰四年任）列在关起（崇宁二年任）之后、周邦彦（元祐八年）之前，次序本身不合。
9. **改自己负责的内容文件不需要外部避让**；任务书里「不要动某文件」只是为了防止两个 agent 撞同一文件。
10. **每条条目都要有「存疑之处」一节**，写清本库无材料判定的是什么，以及「本条只据某一条、本库检索其余各层来源未获可补」这类限度。

## 九、踩过的坑（新增的，省时间）

- **「已取到」不等于「已录入」**。来源卡里写「志文原文已全部取到」而实际只存了名录表，这个落差会让后续 agent 把复原的句子当逐字引文用。凡说「已取到」就必须逐字录入。
- **「逐字录」不许经简体转繁体的手**。2026-10-03 录名宦传时，从 diancang 的简体转录页取文后自行转成繁体当逐字录，事后审计查出 316 处简体字。**转录页若作简体排印，必须另取一份繁体排印的转录页**（shicihui 与 diancang 同书不同排印，取 shicihui）。已写入来源卡使用注意。
- **改既有条目的引文要先备份**：批量替换引文时我因脚本有 bug 把引文截短过，回退靠 `git checkout -- content/lishui-renwu/persons`。**在改存量内容前先确认工作区干净、已提交**。
- **批量改文件前先拿一条样本验工具**：我连写四个脚本都因为引号归一、CRLF、变量遮蔽等问题零替换，白跑多轮。第五次先对单条样本做逐字验证才通过。**先用一条样本验证转换与匹配逻辑，再上批量**。
- **agent 自报完成度不可信**；必须机器对账。
- **自己写的对账脚本也会错**：正则没处理全角括号，把「安应（晬）［睟］」报成缺条目。假阳性要先辨明再下结论。
- **共享信息卡缺字段会让整套取值表空转**。`role`／`birth_era`／`relation` 有取值表、有译法表，但 `InfoCard.astro` 里没有那三行，人物站建站时不会显示。加字段时要同时补：站点取值表、`terms.en.json` 译法组、`ui-default.mjs` 中英标签、组件渲染行。
- **词表断言会先于条目**。`glossary.csv` 里写「刘应雷……隆庆五年溧水知县」，而志文名宦传作「隆庆三年任」、田赋志作隆庆五年丈量——词表把两件事混成一件。词表的人名任年断言要逐条与志文核对。
- **同站同名不报错**。`checkUniqueness` 里有 `if (a.site === b.site) continue;`，唯一性检查是跨站的。两条李衡在人物站列表里会长得一模一样，只能靠 `subtitle` 区分。
- **PowerShell 里多行中文脚本可能挂住不返回**。批量改文件改用 `node -e "..."`（Node 写文件不带 BOM，也不会改行尾）。
- **`git add` 未跟踪文件在 PowerShell 下的 UTF-8 BOM 陷阱**：用 `git ls-files --others --exclude-standard | ForEach-Object { git add "$_" }`。
- **`git push` 偶发连不上 `github.com:443`**（HTTP/2 传输层问题，不是断网）：加 `-c http.sslBackend=schannel -c http.version=HTTP/1.1`。
- **繁体／简体标题混用不会被校验拦住**，只能靠对账脚本发现。
- **agent 会把我写在任务书里的错误照录进条目**。本轮被抓出三处：我把「以通經」写成「由通經」、把荐辟考记年说成只有两处、把贞烈传一处未获的引文当成已有。agent 拒绝引用未获的引文是对的。**任务书不是权威来源，来源卡才是。**
- **英文稿 `summary` 不得含中文字符**（校验拦截），正文里可以放繁体引文。
