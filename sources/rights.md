# 来源层说明

`sources/` 存放的是**来源**，不是内容。这里的每一份文件都只做一件事：把一条外部资料著录清楚，让成果层的条目能挂上一个可追溯、可复核、可判定授权的引用目标。

内容合库后 `sources/` 是**全站群共享**的一层：同一份资料只有一张卡片、一个 `rights` 判定，历史、文化、街镇三站的条目都挂到同一张卡上。来源是「关于世界的证据」，不归任何一站。本文件由原先三库的三份合并而来，差异只在举例，硬规则本就一致。

## 三层目录

| 目录 | 放什么 | 对应 `archive` 取值 |
| --- | --- | --- |
| `fulltext/` | 公有领域旧志的全文或影印本归档。历代《溧水县志》属此类 | `fulltext` / `link-registered` / `catalogued-only` |
| `excerpts/` | 受版权保护资料的摘录卡：只记必要片段与出处，不整篇转录。非遗名录、报刊与学术文章多归此类 | `excerpt` |
| `records/` | 政府页面、区划批复、文保与非遗名录、传统村落名录的链接档案。只记链接、访问日期与关键表述 | `link` |

## 来源记录的字段

每份来源是一张 `.md` 卡片，front-matter 字段如下：

```yaml
id: src:njls-xzqh                      # 唯一标识，格式 src:<短名>，全局不重复
type: gov                              # 取值见 lishui-kit/schema/enums.common.json 的 sourceType
title: 溧水区人民政府网站「行政区划」
titleEn: Administrative Divisions — Lishui District People's Government
rights: gov-open                       # public-domain / gov-open / excerpt-only / link-only / permission-required
reliability: primary                   # primary / secondary / tertiary（见下节）
archive: link                          # fulltext / link-registered / catalogued-only / excerpt / link
publisher: 南京市溧水区人民政府          # 出版者、版本或发布机构
publisherEn: People's Government of Lishui District, Nanjing   # publisher 为中文时必填
url: http://www.njls.gov.cn/zjls/xzqh/ # 可访问地址；无在线版本的写 null 并在 note 说明
accessed: 2026-09-26                   # 访问日期，链接类必填
locator_hint: 页面段落与「名称/面积/政府驻地」表    # 该来源通常怎么标注位置，供条目引用时参照
note: 说明                             # 授权判断依据、存疑之处、归档状态
```

## 可信度分级：`rights` 管能不能引，`reliability` 管可不可信

**这是两个独立维度，不可混为一谈。** `rights` 回答「能不能引、以什么方式引」（授权与版权）；`reliability` 回答「这东西可不可信」（真伪与权威性）。一张网传宣传稿的 `rights` 可以是 `excerpt-only`（法律上可引），但 `reliability` 是 `tertiary`（不可作为事实依据）。**授权干净不等于内容可信。**

2026-09-29 复审时新增此字段。此前 307 张卡无一张有独立可信度标记，可信度只散落在 `note` 的自由文本里——**不可统计、不可校验、无法据以判断某条结论的支柱够不够硬**。

三级取值与判据：

| 取值 | 含义 | 判据 | 本库实例 |
| --- | --- | --- | --- |
| `primary` | **一手** | 公布文件本身、名录正文、点校本正史、原始统计 | 市政府公布件、国图影印志书、统计局公报 |
| `secondary` | **二手转述** | 报道、著录、研究论文对材料的转引、古籍的现代网络转录 | 党媒报道、期刊论文、古籍网络转录本 |
| `tertiary` | **弱来源** | 自办页、论坛、地方文史稿、宣传稿、百科、商家页面 | 景区自办页、祠堂网、设计方自述 |

配套四条：

1. **`reliability` 必填，且须与 `note` 一致。** 填 `tertiary` 就必须在 `note` 写明弱在哪（自办无依据／转述二手／作者与出处不明）。
2. **`tertiary` 不得单独支撑任何事实。** 条目引它作依据时，正文须标明「据××（弱来源）」，且该事实不得单独用来抬升 `confidence`。
3. **古籍网络转录一律 `secondary`**，并在 `note` 写「据网络转录，未核点校本纸面」。本库五部旧志与新增正史、实录、会典、通志**目前全部是 `secondary`**，这是专业度上最大的一笔欠账。
4. **一份来源可因具体用法而降级。** 名录公布件本身是 `primary`；但若某条目用其中的「坊间传说」栏作事实依据，则该用法须按 `tertiary` 对待。分级看的是「这一条引用」，不是「这一份资料」。

**如何改动存量 307 张卡**：已于 2026-09-29 一次性补齐，**不逐条重写 `note`**，只新增字段。分类依据是各卡的 `publisher`、`type`、`note` 实际写了什么，不是按目录一刀切——同在 `excerpts/` 里的既有百科词条，也有《方言》1985 年的期刊论文。补齐结果：

| 可信度 | 张数 | 主要构成 |
| --- | --- | --- |
| `primary` 一手 | 183 | 政府公布件、名录、批复、答复 |
| `secondary` 二手转述 | 87 | 党媒与央媒报道、学术著录、**全部史籍网络转录** |
| `tertiary` 弱来源 | 37 | 百科词条、景区自办页、宣传稿、地方文史稿、设计方自述 |

三条判定经验值得记住：

1. **`type: academic` 不等于可靠。** 本库 `baike-lishuihua` 就登记为 academic，但载体是百科词条，须判 `tertiary`。**先排除弱来源载体，再谈刊物与卷期页。**
2. **央媒与省级党媒是 `secondary`，不是 `tertiary`。** 它们有采编责任；但若稿源是党媒而载体是博客转载页，仍按载体判弱来源。
3. **史籍一律 `secondary`（当前状态）。** 旧志点校本与影印本本身是 `primary`，但**本库全部据网络转录核读**，故一律 `secondary` 并标未核纸面。核到影印本后可改回。

**校验器已同步**（`lishui-kit/validate/engine.mjs`）：`reliability` 缺失或取值不在表内均报错，不只是警告——漏标就看不出「某条结论的支柱有多硬」。台账亦增设「可信度」一列与一行分布汇总。

## 来源台账

台账由 `scripts/ledger.mjs` 现场生成，把本目录每张卡片与 `content/` 下四个分站的实际引用交叉起来，回答四个问题：有哪些来源、每份是什么性质与授权、被哪些条目用着、哪些建了还没用上。

```powershell
npm run ledger --prefix lishui          # 生成三份到 sources/
node scripts/ledger.mjs --csv           # 只出 CSV
node scripts/ledger.mjs --quiet         # 不打印统计摘要
LISHUI_LEDGER_DIR=<目录> node scripts/ledger.mjs   # 输出到别处
```

产出三份，均为派生产物、不进版本库（`.gitignore` 已排除，理由同 `dist/`）：

| 文件 | 用途 |
| --- | --- |
| `ledger.csv` | 一行一张卡片，UTF-8 带 BOM，Excel 与 pandas 直开 |
| `ledger.json` | 同数据加汇总块，供脚本与页面消费 |
| `ledger.html` | 可读视图：KPI、分层结构、机构层级、四站依赖、被引排行、未被引用清单、无链接清单、全量清单（可搜索与多维筛选，跟随系统深浅色） |

站点清单取自 `schema/sites.json`，新增分站后重跑即自动纳入。统计口径以**成果层的 `ref` 出现次数**为准；中英两稿引用同一张卡，故每站数字是条目数而非条目数×2。

## 采集面与存量推进

`collection-plan.md` 定四件事：**每条内容采集时要扫的七层来源**（官方网页、公布文件与名录、地方志系统、学术论文、古籍全文、媒体报道、地图实测）、**一处所一条目的唯一性约束**（第〇节，含全库 9 组已知重复与合并判据）、**质量三底线**（第〇之二节：七维写全、专业可核查、全域无遗漏，含「库建完美」的六项完成标志）、以及**266 个存有条目的五批审计安排**（A 历史站 stub 14 条、B 文化站单引 19 条、C 历史站单引 38 条、D 历史站 standard 90 条、其余三站 122 条，F 批处理跨站重复与全域主题清单）。

要点五条：先查权威层再查媒体层；学术文献未取得原刊时只记著录、正文不取数据；某层查过没有要在条目存疑节写明「本库检索××未获」；**一处所只写一条、写全它，各站取用而不另立**；**先把库建完美，再按主题派生网站，不为凑网页而写条目**。台账是它的量测工具——单引条目数、stub 数、`confidence` 分布三项都从台账读。

## 硬规则

0. **一处所一条目。** 同一处所（一个地点、一项物、一件事、一个人物）在本库只能有一条条目，分站网站不另立内容，只从这一条按本站主题取用所需部分。写任何条目前先搜同 slug、同 id、同 address、近重复标题，命中即视为既有条目——**补它，不新建**。唯一的一条要把该处所的全部已核事实写进去，不按站裁剪；「分站差异」体现在取哪段，不体现在写不写。**确属「同一地点的不同实体」而不该合的**（行政区划 vs 山体、行政村 vs 村内聚落、文保建筑群 vs 纪念地、文物本体 vs 非遗项目名、山上的石刻 vs 山体），在条目 `distinct_from` 里**互向**写明对方条目 id——单方声明不算，须两边都核对过。合并判据与已处理的 10 组重复见 `collection-plan.md` 第〇节。
0.1 **七维写全（丰富）。** `depth: full` 的条目要把七维都写过一遍：身份、来历、形制、制度、人物、生活、限度。缺哪一维就明写「本库未获」，**不许靠别处凑字数，也不许为凑网页而写条目**。「丰富」指维度不缺，不是篇幅长。
0.2 **专业＝可核查。** 每个事实都要能落到某张卡的 locator；来源层级必须显形（网络转录须标「据网络转录，未核点校本纸面」，媒体须标「二手报道」，弱来源在正文与 `note` 双处标明）；矛盾并列不取舍并降 `confidence`；中英专名对照词表。
0.3 **库优先、网站派生（次序）。** 内容库是产品，网站是视图。次序只有一条：来源归档 → 库内条目（唯一、丰富、专业）→ 主题清单无遗漏 → 库建完美 → 按主题派生网站。**网站不生产内容**：库里没有的，网站上也就不该有。
1. **`rights` 必须填，且必须是取值表里的取值之一。** 站群共用的八项取值在 `lishui-kit/schema/enums.common.json`，分站特有的在 `schema/sites/<siteId>.json`。判不准就填 `permission-required`，宁可不引。
2. **无来源的事实不进 `published`。** 条目引用的每一个 `ref` 都必须在本目录下存在对应卡片。
3. **摘录不越界。** `rights` 为 `excerpt-only` 或 `link-only` 的来源，正文里只能引用事实与必要短句，不得整段转录；旧志原文属公有领域的，引用也需标卷次页码，不整篇搬运。
4. **链接要复核。** 政府页面会改版、名录会调整批次、行政区划会调整，`accessed` 字段用于记录核对日期；链接失效时先降级 `confidence`，再找替代来源。
5. **弱来源要显形。** 来源为资料整理页面、地方文史页、论坛、自媒体或二手转述的，`rights` 照填，但在 `note` 里写明权威性不足，并在条目里相应降低 `confidence`。主流媒体与政务融媒体的二手报道不属此类，`note` 写明「二手报道，权威性中等」即可，条目 `confidence` 不超过 `medium`。
5.1 **`reliability` 必填（三级：`primary` / `secondary` / `tertiary`）。** 这是与 `rights` 独立的第二个维度：`rights` 管能不能引，`reliability` 管可不可信，**授权干净不等于内容可信**。`tertiary`（自办页、宣传稿、论坛、百科、地方文史稿）**不得单独支撑任何事实**，作依据时正文须标明弱来源，且不得据以抬升 `confidence`。古籍与正史的网络转录一律 `secondary`，并须在 `note` 写明「据网络转录，未核点校本纸面」——**本库五部旧志与新增正史类目前全部属此，是专业度最大的一笔欠账**。分级看的是「这一条引用」的用法，不是「这一份资料」通身。
6. **名录口径优先。** 文保单位、非遗项目、传统村落的级别、批次与公布年份，一律以官方名录页与公布文件为准；地方介绍页、答复件与新闻报道的累计数与之不一致时，正文并列呈现，不做加总改写，差异写入「存疑之处」。
7. **行政区划事实以政府公开文件为准。** 面积、驻地、下辖村社区数、撤镇设街道的时点，一律以区政府页面与省政府批复为准；地方文史页与论坛的说法只能作地名由来的线索，且必须标为传说。
8. **中英成对，`related` 可跨站。** 任何一侧改动，另一侧同步。`related` 引用的 id 必须真实存在，校验器逐条核；**跨站 `related` 自 2026-09-30 起放行**，渲染为目标站的绝对外链（一处所只在「首发站」成条，另一站指向它即跨站），指向不存在的条目仍判错。旧 id 因合并而停用时，**必须在条目正文写明迁移关系**，否则后人无从判断某条 `related` 是笔误还是迁移遗留。
